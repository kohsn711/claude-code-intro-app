# 0001 文書を正本とするCodex中心の開発運用

- Status: accepted
- Date: 2026-08-12

## 背景

個人開発を再開するにあたり、長いチャット履歴だけでは現状、決定、次の作業を新しいAIセッションへ正確に引き継げない。参考テンプレートは有用だが、全機能を導入すると運用負荷が増える。

## 決定

- Codexを主な開発エージェントとする。
- 要件、計画、設計、運用、チケットを`docs/`内の正本文書へ分離する。
- 参考テンプレートになかった`docs/operations/`を独自に採用し、継続参照する運用手順を個別チケットから分離する。
- 個別作業の状態と進捗は各チケットだけに持たせる。
- 作業終了時はプロジェクト内の`wrap-up` Skillで文書更新、検証結果、次セッション案を確認する。
- CI、gitleaks、Dependabotを導入する。pre-commit hookと自動コミットは導入しない。

## 影響

セッションをまたぐ開発をGit上の情報から再開できる。一方、コード変更によって古くなる文書は同じPRで更新する必要がある。運用が実際に有効か、新規セッションでコールドスタート試験を行う。
