# びーびー日記 要件定義書

この文書をプロダクト要件の唯一の正とする。機能範囲を変更するときは、コードと同じPRで更新する。

## 1. 目的

中高生の野球選手が、日々の練習・生活・体調をスマートフォンから無理なく記録し、監督と保護者の支援を受けながら継続できるかを検証する。

MVPの最重要目的は、学生が日々の記録を継続できるかを検証すること。

## 2. 対象ユーザー

| ロール | 役割 |
| --- | --- |
| Student | 自分の記録と目標を作成・編集・閲覧する |
| Coach | 所属チームの選手記録・目標を閲覧し、反応を返す |
| Parent | activeな親子リンクで結ばれた子どもの記録を閲覧し、反応を返す |
| Admin | コンテンツを管理する。実利用開始前にユーザー管理も追加する |

## 3. 機能要件

### 認証・アカウント

- メールアドレスとパスワードでログインする。
- 保護者の初回設定ではメールOTPを使用する。
- 未認証ユーザーを保護画面からログイン画面へ戻す。
- 初回設定で学生または監督の表示名を設定する。
- 現状、学生・監督のAuthアカウントはSupabase Dashboardで管理者が作成する。
- 実利用開始前に、管理画面から学生・監督を招待し、一覧・検索・停止・監査ログを扱えるようにする。
- 保護者は学生からの招待フローを維持する。
- 実利用開始前に、本人がメールから行うパスワード再設定を追加する。

### 学生

- 学年、ポジション、表示名を設定する。
- チームコードで複数チームへ参加できる。
- 1日1件の日次記録を作成・編集・閲覧できる。
- 練習、体づくり、食事、睡眠・体調、ケガ・痛み、振り返りの6カテゴリを扱う。
- すべての入力項目は任意とし、一部カテゴリだけでも保存できる。
- カレンダー、記録済み日、連続記録日数、最近の反応を表示する。
- 複数目標を作成・編集し、active / achieved / abandonedを管理する。
- 保護者をメールアドレスで招待できる。
- リアクション・コメント通知を閲覧し、既読化できる。
- 学生向けに公開されたコンテンツを閲覧できる。

### 監督

- チームを作成し、参加用チームコードを発行する。
- 所属チームの学生一覧、最終記録日、記録、目標を閲覧する。
- 所属学生の記録へリアクションと200文字以内のコメントを送信する。
- 監督向けに公開されたコンテンツを閲覧する。

### 保護者

- 学生から届いた招待を承認または拒否する。
- 複数の子どもと連携できる。
- activeな親子リンクの子どもの記録だけを閲覧する。
- 子どもの記録へリアクションと200文字以内のコメントを送信する。
- 保護者向けに公開されたコンテンツを閲覧する。

### 管理者・コンテンツ

- 記事・外部動画コンテンツを作成・編集する。
- draft / published / archivedを管理する。
- 学生・保護者・監督から公開対象を複数指定する。
- Supabase Storageへサムネイルをアップロードする。

### コメント・通知の可視性

- 学生は監督と保護者双方のコメント・リアクションを閲覧する。
- 監督は監督が送信したものだけを閲覧する。
- 保護者は保護者が送信したものだけを閲覧する。
- コメント・リアクション作成後、DBトリガーで対象学生のアプリ内通知を作る。

## 4. データ要件

- 日次記録は学生と日付の組み合わせで一意とする。
- 記録の詳細構造は[データモデル](design/data-model.md)を正とする。
- 学生記録は本人、所属チームの監督、activeな親子リンクの保護者だけが閲覧できる。
- チームメイトには他の学生の記録を公開しない。
- 健康・ケガ情報は医療判断ではなく本人による記録として扱う。
- 退会後のデータ保持・削除期間は、実利用開始前の規約整備で決定する。

## 5. 非機能要件

### 利用環境

- スマートフォンを主対象とする。
- 最低限の記録を約1分で完了できることを優先する。
- PWA Phase 1としてホーム画面追加とstandalone起動を提供する。
- オフライン対応とWeb Pushは将来対応とする。

### セキュリティ

- Supabase RLSとアプリ側認可を併用する。
- 秘密情報をブラウザバンドルやGitへ含めない。
- 未成年者の個人情報を扱うため、利用規約、プライバシーポリシー、保護者同意の方法を実利用開始前に専門家確認する。

### 可用性・運用

- Vercelをアプリの本番環境、SupabaseをAuth・DB・Storage環境とする。
- 現在はVercel Hobby、Supabase Freeを利用する。
- 実利用開始前は本番DBマイグレーション前と本番リリース前に手動バックアップする。
- 実利用開始後はバックアップ頻度と有料プランを再評価する。

## 6. MVP対象外・将来対応

- 試合結果・個人成績・ランキング
- チームメイトへの記録公開、SNSフィード
- 自前動画アップロード、広告、決済、物販
- LINE / Google / Appleなどの外部ログイン
- ネイティブアプリ、複雑な分析ダッシュボード
- オフライン利用、Web Push
- 自動テスト、外部エラー監視、Web Analytics、Speed Insights

## 7. 検証計画

- MVP期間中は変更機能と主要な認証・権限境界を手動確認する。
- PRではlint、型チェック、本番ビルドをCIで自動確認する。
- 本番リリース後にProduction Deploymentと変更箇所をスモーク確認する。
- 本格利用時の成功基準は、記録継続率などの定量指標をトライアル計画時に決定する。
